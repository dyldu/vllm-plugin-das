# DSpark runtime capacity and fusion admission (2026-11-20)

`max-num-seqs`, `max-num-batched-tokens`, and draft count are runtime inputs. This change removes the previous `(256,32,5)` gate and the requirement that every request slot fit a simultaneous full verification pass. Target rows stay bounded by the user's budget. Private draft/transport rows use `max(target_budget, native_active_requests * query_rows_per_request)`, preserving native scheduling policy and request-slot allocation. Builds without a separate active bound use request slots. Actual and padded batches are checked before writes or launch.

The current validation fixture uses 64 request slots, budget 256, max-model-len 32768, TP1/DP8/EP8, drafts 5 and FULL_AND_PIECEWISE graphs. These numbers are test settings, not serving admission conditions. Native vLLM derives 51 active requests per rank; the resulting draft/transport capacity remains 256. The implementation can enlarge private draft rows when another valid configuration requires it without changing target scheduling arguments.

WO_A, QKV, RMS INT8, mHC, sparse MLA IO/selectors/inverse RoPE, indexer postprocessing/native TopK, greedy selection and receiver/MoE workspaces no longer admit work by incidental M buckets. Existing model geometry, device architecture, packed-weight ABI, supported selector width/native Top512 limits, dtype, layout, provider identity and ownership checks remain. RMS follows the native reduction switch at M=256 on both fused routes. Unsplit mHC projection keeps native arithmetic with optimized Post. GEMM Mode1070 receives its 3D descriptor through a zero-copy view of the same packed storage.

Operator checks include byte-exact native RMS/quantization at M=255/256/257; 86 RMS weights; owned GEMM consumers; fresh graph metadata; receiver capacities 128..512; greedy request counts 1/17/32/64 and draft lengths 1/3/5/7; WO_A through M=256; mHC Post through M=2048; MLA and TopK through M=256. Native TopK preserves score ranks and its existing tie policy, rather than promising identical tied membership to torch.topk. Its real MLA consumer oracle uses unique scores.
